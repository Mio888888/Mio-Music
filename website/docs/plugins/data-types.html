// Data Types

数据结构

插件返回的 JSON 会被反序列化为 mio-music-sdk 里的 Rust 类型。字段名与类型必须对得上，否则整次调用会失败。本页列出每一种结构。

先记住这三条
  • 大多数结构的字段名是 camelCase（albumName、allPage）。发现页的结构例外，用的是 snake_case（has_more、update_frequency），见 发现页。
  • 类型要严格：该是字符串的字段给了数字（或相反）就会失败。整数字段必须是有限的整数，NaN、Infinity 与 3.5 都不行（JSON.stringify 会把 NaN 变成 null）。
  • 失败时用户只会看到「插件返回的数据格式无效」，具体是哪个字段错了，在 插件日志 里。

下面表格的「必填」列表示：缺少该字段时反序列化是否失败。「可选」字段缺失时取默认值（空串、null 或 0）。

MusicItem（歌曲）

歌曲在列表里出现、被收藏、加入歌单、下载，最后又作为 song 参数传回你的 musicUrl / lyrics 等方法，都是这个结构。所有字段都是可选的，但实际上请至少填写前面几项。

字段类型说明
songmidstring | number歌曲在来源里的唯一 ID。建议用字符串。
namestring歌名。
singerstring歌手名，多个歌手自行拼接。
albumNamestring专辑名。
albumIdstring | number专辑 ID，之后可用于 albumDetail。
singerIdstring歌手 ID，用于跳转到歌手页。
sourcestring来源 ID。宿主会改写成本次调用的来源，但仍建议填写。
intervalstring时长，格式 mm:ss（或 hh:mm:ss）。
imgstring封面 URL，没有则空串。
typesstring[]这首歌可用的音质名称（128k、320k、flac …），由差到好。
_typesobject各音质的补充信息：{ "320k": { size: "9.8MB", hash?: "…" } }。size 是字符串。
typeUrlobject私有数据的容器，见下文。
lrcstring | null已经附带的歌词文本，通常为 null。
hash、songId、strMediaMid、albumMid、copyrightId、lrcUrl、mrcUrl、trcUrl各异原版若干来源用到的额外字段，自建来源一般不需要。

字符串类型的字段（name、singer、albumName、interval、img 等）如果传了数字，整个结果都会被拒绝。服务器返回数字的时候，用 String(v) 转换一下。

私有数据放在哪里

歌曲会被缓存、写入收藏与歌单、交给下载器，再在播放时传回你的方法。这个过程通过 MusicItem 结构往返，所以结构里没有的字段会丢失——你自己加的 serverPath、token 之类的顶层字段，到 musicUrl 时已经不在了。两个办法：

  • 把定位歌曲所需的一切编进 songmid（例如 "srv1:12345"），在方法里再拆开；
  • 或把私有字段放进 typeUrl 对象。typeUrl 是自由结构，会随歌曲完整保留，旧版服务适配层也用它保存原始来源。
function toSong(v) {
  return {
    songmid: String(v.id),
    name: String(v.title || ''),
    singer: String(v.artist || ''),
    albumName: String(v.album || ''),
    source: 'myid',
    interval: mmss(Math.trunc(v.duration) || 0),
    img: coverUrl(v),
    types: ['128k', '320k'],
    typeUrl: { path: v.path },   // 私有数据：播放时从 song.typeUrl.path 读回
  };
}

发现页

这里的字段是 snake_case 发现页的结构沿用了原版的序列化格式：用 has_more 和 update_frequency，不是 hasMore 和 updateFrequency。写成 camelCase 会得到「字段缺失」的错误。其中嵌套的 PlaylistItem、MusicItem 仍然是 camelCase。

Lyric（歌词）

字段类型说明
lyricstring逐行 LRC 文本，每行形如 [mm:ss.xx]歌词。既没有 lyric 也没有可解析的 ttml，就视为没有歌词。
tlyricstring翻译 LRC，时间轴与 lyric 对应，没有就留空。
rlyricstring音译（罗马音）LRC，没有就留空。
crlyricstring来源特有的逐字歌词文本，一般留空。
sourcestring来源 ID。
ttmlstring可选。带逐字时间的 TTML 文档。提供它，歌词页就能做逐字高亮。可用 cerumusic.utils.lyric.validTtml 事先校验。

整个返回值序列化后不得超过 4 MB。服务器没有歌词时，throw new Error('没有找到歌词')，而不是返回空对象。

Comments（评论）

{
  comments: [
    {
      id: '123',               // 用于去重，必须唯一
      userName: 'Mio',
      avatar: 'https://…',
      timeStr: '2026-10-01',
      text: '好听！',
      likedCount: 42,
      images: ['https://…'],   // 可选
      reply: [ /* 同结构的回复，可选 */ ],
    },
  ],
  total: 1280,        // 总评论数
  maxPage: 43,        // 总页数
  cursor: '',         // 下一页游标，没有就空串或省略
}
  • 一页最多 300 条，整体序列化后不超过 4 MB，否则整次调用被拒绝。
  • text 按纯文本展示，宿主会对其中的 HTML 做转义，所以不必也不应当自己转义。
  • avatar 与 images 只接受不含用户名密码的 http(s) 地址，不合法的会被忽略。
  • cursor 只允许字母、数字与下划线，最长 256 个字符。如果连续两次返回的内容相同（id 全部重复），应用会认为已经到底并停止翻页。
